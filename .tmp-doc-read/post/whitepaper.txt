1. 执行摘要
晓软智能体是面向本地工作流的桌面 AI Agent 平台，采用 Electron + React 架构。当前定制版以 AISphere 作为唯一内置模型来源，并提供协作、编程、技能、MCP、定时任务和消息渠道能力。
本白皮书面向技术决策者和架构师，从技术架构、安全模型、性能特性、部署方案和集成能力五个维度阐述 晓软智能体 的技术能力。

2. 产品定位与技术理念
2.1 产品定位
晓软智能体 定位于专业的 AI Agent 桌面工作站，区别于通用聊天类 AI 应用，它提供以下核心价值：
可控性: 模型目录由用户绑定的 AISphere 平台提供，凭据由主进程管理；应用不提供产品账号、免费额度或第三方供应商入口。
可扩展性: 通过技能（Skills）、MCP 协议、自定义供应商实现能力扩展。
工具化: Agent 可调用系统工具（文件读写、终端命令、网络请求），完成实际的工程任务。
多平台覆盖: 同时支持桌面端 Agent 交互和即时通讯端机器人响应。
2.2 技术理念
进程隔离: Electron 主进程、渲染进程、渠道运行时和本地能力服务按边界隔离。
本地优先: 核心数据（配置、会话、模型参数）均存储在本地 SQLite 数据库，云端仅用于模型 API 调用。
文档即代码: 代码与文档同步发布，关键功能必有对应文档覆盖。
开放标准: 采用 OpenAPI、MCP、RRULE 等开放标准，确保互操作性。

安全隔离措施:
contextIsolation: true：渲染进程无权直接访问 Node.js API。
nodeIntegration: false：禁用 Node.js 集成。

4. Agent 引擎子系统
统一 Agent 执行与渠道调度
Work、Chat、Channel 和 Cron 统一使用同一 Agent 执行内核；消息渠道和定时任务只负责接收、调度、投递和活动状态，不拥有独立的 Agent 任务状态。

4.2 统一 Agent 运行时
统一 Agent 运行时 是 晓软智能体 的 Agent 运行时引擎，负责 IM 会话和 Cron 定时任务：
运行方式: 作为独立 Node.js 子进程运行，与主进程通过 HTTP API 通信。
生命周期管理: 统一 Agent 运行时EngineManager 管理安装（从源码构建）、启动、状态监控、崩溃重启。
状态机: not_installed --> ready --> starting --> running | error
配置同步: 统一 Agent 运行时ConfigSync 将 Cowork 配置（模型供应商、认证凭证等）同步为 统一 Agent 运行时 配置文件。
插件体系: 通过 统一 Agent 运行时 插件（企业微信、飞书、钉钉、微信连接器）实现 IM 集成。
本地扩展: 支持加载 openclaw-extensions/ 目录下的本地扩展模块。
4.3 Agent 引擎路由
CoworkEngineRouter 是 Agent 调度的核心路由模块，位于 src/main/libs/agentEngine/coworkEngineRouter.ts。它实现：
引擎分发: 将 Cowork 会话请求路由到活跃的引擎适配器（统一 Agent 运行时RuntimeAdapter）。
流事件转发: 将引擎产生的流事件（消息增量、工具调用、思考链）转发至渲染进程的 IPC 监听器。
权限拦截: 当引擎请求工具执行时，生成 permissionRequest 事件，暂停执行等待用户确认。

5.2 模型生命周期
1. 发现: 通过模型市场搜索或手动导入模型文件。
2. 下载: llamacppModelInstallation 管理下载队列，支持断点续传和进度显示。
3. 安装: 模型文件写入本地存储目录，校验完整性。
4. 启动: 用户选择模型并配置参数后，llamacppServe 启动 llama-server 子进程。
5. 绑定: 运行中的模型通过 LlamaCpp统一 Agent 运行时Binding 注册为 统一 Agent 运行时 的 llamacpp Provider，检查上下文窗口是否满足最低要求后对用户可见。
6. 服务: Client 通过 REST API 与 llama-server 通信，转发推理请求。
7. 停止: 用户停止模型或应用退出时，终止 llama-server 子进程。

6. 安全模型
6.1 进程隔离策略
晓软智能体 实施严格的进程隔离，核心安全措施包括：
渲染进程隔离:
// Electron BrowserWindow 配置 (main.ts:5861-5865)
{
  webPreferences: {
    contextIsolation: true,   // 隔离渲染上下文
    nodeIntegration: false,   // 禁用 Node.js 集成
    webSecurity: true,        // 同源策略
  }
}
// 同时: app.commandLine.appendSwitch('no-sandbox')  // main.ts:810
// Chromium OS 级沙箱在 Windows 下显式禁用，因管理员运行时无法降权
渲染进程所有 Node.js API 访问必须通过 preload 脚本的 contextBridge 暴露的白名单 API。
Content Security Policy 限制可加载的外部资源来源。
子进程隔离:
统一 Agent 运行时 和 llama-server 均作为独立子进程运行。
子进程崩溃不影响主进程和渲染进程。
子进程的网络访问受操作系统级别防火墙控制。
6.2 技能安全扫描
技能包在安装和加载时经过安全扫描流程：
1. 读取技能定义文件（SKILL.md）。
2. 解析技能声明的工具权限和资源访问需求。
3. 检查是否包含危险操作（如未授权的文件系统访问、网络调用）。
4. 不满足安全要求的技能将被拒绝加载。
6.4 API 密钥管理
AISphere 地址和绑定状态按应用配置保存；实际平台凭据仅由主进程持有，不进入渲染进程配置或日志。
支持密码加密导出/导入功能（EncryptedPayload 格式）。
在传输至模型供应商时通过 HTTPS 加密通道发送。
6.5 网络安全
所有对外 API 通信使用 HTTPS。
支持用户自定义代理配置。
网络状态监控，离线时主动通知渲染进程。
消息渠道按区域筛选：中文界面显示微信、钉钉、飞书、企业微信和 QQ；英文界面还显示 Telegram 和 Discord。


7. 性能特性
7.1 流式响应
所有 AI 对话采用 SSE（Server-Sent Events）流式传输。
消息内容实时增量渲染，首字符响应时间（TTFB）依赖模型供应商性能。
本地模型推理延迟取决于硬件配置（GPU 型号、显存大小）。
7.2 会话管理性能
会话列表支持分页加载（COWORK_SESSION_PAGE_SIZE）。
使用 SQLite 索引优化会话查询。
应用启动时采用并发初始化策略（Promise.all 并行加载多个子系统）。
7.3 内存占用
基础应用运行时内存占用约 300-500 MB（Electron + React）。
运行本地模型时额外内存占用取决于模型大小（如 7B 参数量化模型约需 4-8 GB）。
长会话历史存储在 SQLite 中，不占用内存。
7.4 启动性能
冷启动设置了 24 秒超时保护。
初始化阶段有详细的性能标记日志（performance.now()），便于诊断启动瓶颈。


8. 可扩展性设计
8.1 技能扩展体系
技能是 晓软智能体 的一级扩展机制：
技能定义格式: Markdown 格式的 SKILL.md 文件，包含技能描述、触发条件、工具权限声明。
附属资源: 每个技能可携带脚本（scripts/）、参考资料（references/）、资源文件（assets/）。
技能市场: 支持从远程技能市场浏览和安装技能包。
自定义技能: 用户可通过自然语言描述创建自定义技能。
8.2 MCP 协议扩展
晓软智能体 原生支持 MCP 协议，允许接入任何兼容 MCP 标准的工具服务器：
MCP 桥接服务 (McpBridgeServer): 实现 Agent 引擎与外部 MCP 服务器的协议转换。
连通行探测 (mcpConnectionProbe): 支持连接状态验证。
多服务器管理: 支持同时连接多个 MCP 服务器。
8.3 自定义供应商
用户可配置最多 10 个自定义 LLM 供应商（custom_0 至 custom_9），每个供应商可配置：
API Base URL
平台凭据
模型列表（模型 ID、显示名称、是否支持图像）
8.4 统一 Agent 运行时 插件体系
统一 Agent 运行时 支持通过 npm 包形式加载第三方连接器插件：
@wecom/wecom-openclaw-plugin --- 企业微信连接器
@larksuite/openclaw-lark --- 飞书连接器
@dingtalk-real-ai/dingtalk-connector --- 钉钉连接器

13. 版本与兼容性策略
13.1 版本号规范
采用语义化版本号 (Semantic Versioning)：
主版本号 (MAJOR): 不兼容的 API 变更。
次版本号 (MINOR): 向后兼容的功能新增。
修订号 (PATCH): 向后兼容的问题修复。
13.2 向后兼容性
配置文件格式保持向后兼容，新增字段提供默认值。
会话数据格式变更时提供自动迁移逻辑。
技能包规范版本化，旧版技能在新版应用中继续可用。
已有 IPC 通道不会变更或移除，仅新增通道。
13.3 废弃策略
废弃旧版 API 时提供至少一个次版本的过渡期。
过渡期内同时支持新旧接口，并在设置面板中显示升级提示。
废弃功能在文档中标注 @deprecated 及移除时间节点。


14. 总结
晓软智能体 是一个功能完备、架构清晰的桌面 AI Agent 平台。其核心竞争力体现在以下方面：
1. 全栈可控: 从 UI 层到推理引擎层均为自主可控的技术选型，无黑盒依赖。
2. 安全设计: 多层进程隔离、令牌安全管理、技能安全扫描。
3. 高度可扩展: 技能体系、MCP 协议、自定义供应商、统一 Agent 运行时 插件体系构成完整的扩展矩阵。
4. 多端覆盖: 同时支持桌面端 Agent 交互、本地推理和即时通讯端机器人响应。
本地优先: 会话、配置、技能和任务状态保存在本地；当前定制版模型调用依赖绑定的 AISphere，不承诺完全离线运行。
适用于对数据安全有严格要求、需要 AI 工具化能力、期望多平台覆盖的开发者。

15. 当前定制版边界
模型绑定：设置页只提供 AISphere 地址、连接/刷新和平台模型选择。平台发现接口和模型目录由主进程校验，模型请求通过本机网关转发。
身份与更新：不提供产品账号登录、游客令牌、内置免费模型注册、第三方模型供应商配置或产品内自动更新入口。
编程工作台：内置 Agent 与外部 ACP Agent 通过适配器隔离。外部 Agent 使用自己的账号、模型、工具和配置，不接收应用模型凭据。
渠道与定时任务：渠道连接器承载外部消息和投递，定时任务负责触发和记录；两者均调用统一 Agent 执行内核。
