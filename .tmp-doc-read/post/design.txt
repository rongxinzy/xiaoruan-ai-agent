1. 系统概述
1.1 产品定位
晓软智能体是基于 Electron 构建的桌面 AI Agent 应用。当前定制版的模型调用只经过用户绑定的 AISphere 平台；会话、技能、MCP、编程、定时任务和消息渠道状态由本地应用管理。
1.2 核心技术栈

1.3 系统边界
本系统运行于用户本地桌面环境，其核心职责包括：
1. 接收用户自然语言输入，通过 Agent 引擎执行任务编排与工具调用。
管理应用内可用的模型绑定和请求生命周期；本地推理相关代码不作为当前定制版的用户模型入口。
3. 通过 MCP (Model Context Protocol) 协议接入外部工具与数据源。
通过渠道传输组件接入微信、钉钉、飞书、企业微信、QQ，以及英文界面的 Telegram 和 Discord，使 Agent 可响应外部消息。
5. 提供技能（Skill）市场与本地技能管理，扩展 Agent 能力边界。
6. 支持定时任务的创建、管理与调度执行。

3. 进程模型与IPC通信
3.1 进程架构
系统遵循 Electron 双进程模型，严格采用进程隔离策略：

3.2 Preload 桥接层
渲染进程通过 preload.ts 中的 contextBridge.exposeInMainWorld('electron', api) 暴露安全的 API 接口。该层提供了以下核心命名空间：
window.electron.store — 键值存储读写
window.electron.skills — 技能列表、启用/禁用、下载、安装确认
window.electron.mcp — MCP 服务配置 CRUD、连接测试
window.electron.cowork — 会话管理、流式消息监听、权限确认
window.electron.config — API 配置、会话标题生成
window.electron.window — 窗口最小化/最大化/关闭
window.electron.im — IM 实例配置、配对管理
window.electron.log — 日志导出
window.electron.shell — 外部链接打开、文件浏览
3.3 IPC 通道分类
系统定义了 60+ 个 IPC 通道，按功能域组织在 src/shared/ipc/channels.ts 中：
StoreIpc:        store:get | store:set | store:remove
SkillsIpc:       skills:list | skills:setEnabled | skills:delete | ...
McpIpc:          mcp:list | mcp:create | mcp:update | mcp:delete | ...
CoworkSessionIpc: cowork:session:start | cowork:session:continue | ...
CoworkStreamIpc: cowork:stream:data | cowork:stream:error | ...
CoworkPermissionIpc: cowork:permission:request | cowork:permission:respond
CoworkConfigIpc: cowork:config:get | cowork:config:update
CoworkMemoryIpc: cowork:memory:list | cowork:memory:add | ...
渠道与调度运行时EngineIpc: openclaw:engine:getStatus | openclaw:engine:install | ...
ApiIpc:          api:fetch | api:stream | api:stream:cancel
CodingAgentIpc:  coding-agent:workspace | coding-agent:session | coding-agent:git | ...
ImIpc:           im:list | im:create | im:update | im:delete | ...
3.4 IPC 消息安全策略
主进程对所有 IPC 入站消息实施以下约束：
字符串消息最大长度: IPC_MESSAGE_CONTENT_MAX_CHARS = 120,000
更新内容最大长度: IPC_UPDATE_CONTENT_MAX_CHARS = 120,000
通用字符串最大长度: IPC_STRING_MAX_CHARS = 4,000
嵌套对象最大深度: IPC_MAX_DEPTH = 5
单个对象最大键数: IPC_MAX_KEYS = 80
数组最大元素数: IPC_MAX_ITEMS = 40
内联附件最大字节: 25 * 1024 * 1024 (25MB)


4. 主进程架构
4.1 入口文件: main.ts
main.ts（约 264KB，系统最大单体文件）是主进程的总控中心。它负责：
1. 应用生命周期管理: 注册 app.whenReady()、app.on('window-all-closed') 等事件。
2. 窗口创建与管理: 创建 BrowserWindow 实例，配置 contextIsolation、nodeIntegration: false、webSecurity。
3. IPC Handler 注册: 集中注册所有 IPC invoke/handle 通道（40+ 个处理函数）。
4. 子系统初始化: 按依赖顺序初始化各核心模块。
4.2 核心子系统初始化顺序
基于 main.ts 中 app.whenReady() 回调的代码逻辑，子系统初始化顺序如下：
1. SqliteStore.create()         -- 数据库初始化（含自动备份恢复）
2. CoworkStore.create()          -- Cowork 存储初始化
3. SkillManager.loadSkills()     -- 技能加载与安全扫描
4. McpStore / McpServerManager   -- MCP 服务管理
5. 渠道与调度运行时EngineManager         -- 渠道与调度运行时 运行时引擎
ChannelRuntime               -- 消息渠道与定时任务运行时
7. IMGatewayManager              -- IM 网关管理
4.3 关键子模块详细设计
4.3.1 SqliteStore (sqliteStore.ts)
SqliteStore 是系统的持久化核心，基于 better-sqlite3 实现。数据表设计如下：
kv 表 — 通用键值存储：
CREATE TABLE IF NOT EXISTS kv (
    key   TEXT PRIMARY KEY,
    value TEXT NOT NULL,
    updated_at INTEGER NOT NULL
);
存储内容包括：API 配置、模型配置、IM 实例配置、MCP 服务配置、定时任务、窗口状态等。
cowork_sessions 表 — 会话记录：
CREATE TABLE IF NOT EXISTS cowork_sessions (
    id              TEXT PRIMARY KEY,
    title           TEXT,
    status          TEXT NOT NULL DEFAULT 'active',
    created_at      INTEGER NOT NULL,
    updated_at      INTEGER NOT NULL,
    workspace_id    TEXT,
    pinned          INTEGER DEFAULT 0,
    execution_mode  TEXT DEFAULT 'auto',
    agent_id        TEXT,
    expert_ids      TEXT,  -- JSON array
    model_override  TEXT,
    ...
);
cowork_messages 表 — 会话消息记录：
CREATE TABLE IF NOT EXISTS cowork_messages (
    id          TEXT PRIMARY KEY,
    session_id  TEXT NOT NULL,
    role        TEXT NOT NULL,
    content     TEXT NOT NULL,
    created_at  INTEGER NOT NULL,
    metadata    TEXT,
    ...
);
支持分页查询：会话列表每页 COWORK_SESSION_PAGE_SIZE 条，消息列表每页 COWORK_MESSAGE_PAGE_SIZE 条。
数据库启动时执行健康检查，失败时自动从 SQLite 备份恢复。
4.3.2 CoworkStore (coworkStore.ts)
CoworkStore 管理 Cowork 会话的完整生命周期：
会话 CRUD: createSession(), getSession(), listSessions(), updateSession(), deleteSession()
消息 CRUD: addMessage(), getMessages(), prependMessages(), updateMessageContent()
内存管理: memoryEnabled, memoryImplicitUpdateEnabled, memoryGuardLevel（strict/standard/relaxed）
分页支持: listSessions() 支持基于游标的 pageSize 分页
4.3.3 SkillManager (skillManager.ts)
SkillManager 管理系统中的技能定义（约 103KB），核心功能：
1. 技能发现: 扫描 SKILLs/ 目录下的技能定义（SKILL.md）。
2. 技能安装: 支持从 ModelScope 市场、GitHub 仓库等来源下载安装。
3. 安全扫描: 安装前对技能目录执行安全扫描（skillSecurity/），生成安全报告。
4. 配置管理: skills.config.json 控制技能的启用/禁用与加载顺序。
5. 运行时环境: 解决用户 Shell PATH，确保 Node.js/npm 可用。
4.3.4 SkillServices (skillServices.ts)
SkillServiceManager 负责管理技能运行所需的常驻后台服务。当前实现聚焦于 Web Search 桥接服务器的生命周期管理：
启动 Web Search Bridge Server（检测运行环境、自动修复依赖与编译产物）。
健康检查：通过 http://127.0.0.1:8923/api/health 端点探测服务状态。
进程管理：PID 文件持久化，SIGTERM 优雅停机。
环境构建：buildSkillServiceEnv() 解析用户 Shell PATH，为子进程提供正确的 Node.js 运行时路径。
通过 getSkillServiceManager() 获取全局单例。

7. Agent引擎子系统
7.1 双内核架构
系统采用双内核（Dual-Kernel）设计，两个引擎按场景分工，通过统一的 CoworkRuntime 接口向渲染进程屏蔽差异：
// src/main/libs/agentEngine/types.ts
export type CoworkAgentEngine = 'openclaw' | 'pi';
 
export interface CoworkRuntime {
  on<U extends keyof CoworkRuntimeEvents>(event: U, listener: ...): this;
  startSession(sessionId: string, prompt: string, options?: CoworkStartOptions): Promise<void>;

两个引擎均通过 bindCoworkRuntimeForwarder() 注册到 IPC 事件转发层，渲染进程接收的 cowork:stream:* 消息透明地来自两个内核：
// src/main/main.ts:1614-1618
// Dual-kernel: bind both 统一 Agent 执行内核 (Work sessions) and 渠道与调度运行时 (IM sessions).
// Both feed into the same cowork:stream:* IPC channels so the UI shows
// messages from both sources.
forwardRuntimeToRenderer(get统一 Agent 执行内核RuntimeAdapter());       // Work → 统一 Agent 执行内核
forwardRuntimeToRenderer(get渠道与调度运行时RuntimeAdapter());     // IM → 渠道与调度运行时
7.2 统一 Agent 执行内核 Runtime Adapter (piRuntimeAdapter.ts)
统一 Agent 执行内核 负责 Work 会话（用户在工作台 UI 中主动发起的协作对话），约 59KB 实现文件。cowork:session:start IPC 处理器直接调用 get统一 Agent 执行内核RuntimeAdapter() 启动会话（main.ts:3359），无需等待 渠道与调度运行时。
技术实现：
运行方式: 直接导入 @earendil-works/pi-coding-agent 和 @earendil-works/pi-ai 包，在 Node.js 主进程中运行，无子进程开销。
会话创建: 通过 createAgentSession() 创建 AgentSession 实例，session.subscribe() 注册事件监听。
流式输出: 支持 text_delta / thinking_delta 粒度的增量事件，分别映射到 UI 的回答气泡和思考气泡。
模型支持: 支持本地 Provider（本地推理组件）和全部云端 Provider。
会话状态: 维护 Active统一 Agent 执行内核Session 结构，包含 assistantMessageId、thinkingMessageId、answerText、thinkingText 等状态字段。
工具调用: 完整追踪 tool_execution_start / tool_execution_update / tool_execution_end 事件链。
权限模型: 支持 modal 模式（弹窗确认）和 text 模式（文本确认）。
7.3 渠道与调度运行时 Runtime Adapter (openclawRuntimeAdapter.ts)
渠道与调度运行时 负责 IM 会话（企业微信、飞书、钉钉、微信等平台消息驱动的对话）和 Cron 任务（定时任务调度执行），约 240KB 实现文件。其架构特点：
运行方式: 渠道与调度运行时 作为独立子进程运行（UtilityProcess），通过 WebSocket 与主进程通信。
引擎管理: 渠道与调度运行时EngineManager 管理 Gateway 子进程生命周期，状态包括：not_installed -> installing -> ready -> starting -> compiling -> running -> error。
Gateway 端口: 默认端口 18789，启动时自动扫描可用端口（扫描范围 80 个端口）。
启动超时: 冷启动 600 秒（含 V8 编译），预热启动 300 秒。
重启策略: 最多 5 次重试，延迟递增（3s -> 5s -> 10s -> 20s -> 30s）。
Channel Session: 基于 渠道与调度运行时ChannelSessionSync 的 channel session 机制，通过 buildManagedSessionKey 映射会话标识，实现 IM 平台 ↔ Session 绑定。
消息流: 通过 Gateway 的 WebSocket 事件流接收 Agent 消息、工具调用、权限请求等。
权限模型: 支持 modal 模式（弹窗确认）和 text 模式（文本确认）。
